# Hotel Reservation API

![CI](https://github.com/AyaChatiou/hotel-reservation-api/actions/workflows/ci.yml/badge.svg)
![Python](https://img.shields.io/badge/python-3.11%20%7C%203.12-blue)
![FastAPI](https://img.shields.io/badge/FastAPI-0.115-009688)
![License](https://img.shields.io/badge/license-MIT-green)

A small, production-shaped REST API for managing hotel rooms and reservations —
built to demonstrate clean CRUD design, JWT authentication, real business-logic
testing (date-overlap conflict detection), and a working CI/CD pipeline.

This project is a from-scratch rebuild of an earlier academic reservation-system
project, this time as a fully tested, containerized, deployable service.

## Features

- **JWT authentication** — register, login, protected routes
- **Room management** — create, list, retrieve, deactivate
- **Reservations** — create, list, cancel, with **automatic date-overlap conflict detection**
  (you cannot double-book a room for overlapping dates)
- **20 automated tests** covering happy paths, edge cases, and auth failures
- **CI pipeline** (GitHub Actions) running lint + tests on every push, across Python 3.11 and 3.12
- **Dockerized**, ready to run with a single command
- Interactive API docs auto-generated by FastAPI (Swagger UI + ReDoc)

## Tech stack

| Layer          | Choice                          |
|----------------|----------------------------------|
| Framework      | FastAPI                          |
| ORM            | SQLAlchemy 2.0                   |
| Validation     | Pydantic v2                      |
| Auth           | OAuth2 password flow + JWT (python-jose), bcrypt password hashing |
| Database       | SQLite (swappable via `DATABASE_URL`) |
| Testing        | Pytest + FastAPI `TestClient`     |
| CI             | GitHub Actions                    |
| Containerization | Docker / docker-compose         |

## Architecture

```
Client
  │
  ▼
FastAPI routes (app/main.py)
  │        │
  │        ▼
  │   auth.py  ── JWT issuing / verification, password hashing
  │
  ▼
schemas.py (Pydantic)  ── request/response validation
  │
  ▼
models.py (SQLAlchemy)  ── User, Room, Reservation
  │
  ▼
database.py  ── engine / session, swappable via DATABASE_URL
```

## Getting started

### Option A — Docker (recommended)

```bash
docker compose up --build
```

The API will be available at `http://localhost:8000`.

### Option B — Local Python environment

```bash
python -m venv venv
source venv/bin/activate      # Windows: venv\Scripts\activate
pip install -r requirements.txt
uvicorn app.main:app --reload
```

### Explore the API

Once running, open:
- **Swagger UI:** http://localhost:8000/docs
- **ReDoc:** http://localhost:8000/redoc

### Quick walkthrough

```bash
# Register
curl -X POST http://localhost:8000/auth/register \
  -H "Content-Type: application/json" \
  -d '{"email":"me@example.com","password":"supersecret1","full_name":"Aya"}'

# Log in (get a token)
curl -X POST http://localhost:8000/auth/login \
  -d "username=me@example.com&password=supersecret1"

# Create a room (use the token from above)
curl -X POST http://localhost:8000/rooms \
  -H "Authorization: Bearer <TOKEN>" \
  -H "Content-Type: application/json" \
  -d '{"number":"101","room_type":"single","price_per_night":89.0}'

# Book it
curl -X POST http://localhost:8000/reservations \
  -H "Authorization: Bearer <TOKEN>" \
  -H "Content-Type: application/json" \
  -d '{"room_id":1,"check_in":"2026-10-01","check_out":"2026-10-05"}'
```

## Running the tests

```bash
pip install -r requirements-dev.txt
pytest -v
```

All 20 tests run against an in-memory SQLite database, so they're fast and
leave no artifacts behind. The suite covers:

- Registration / login / duplicate-email handling
- Auth-protected routes correctly rejecting unauthenticated requests
- Room CRUD, including duplicate room numbers and inactive-room filtering
- **Reservation conflict detection** — the core business rule: two reservations
  on the same room cannot have overlapping date ranges, but back-to-back or
  cancelled reservations correctly free up the room

## What this project demonstrates

This project was built as a portfolio piece to show, end to end:
- Designing a relational schema with real constraints (foreign keys, uniqueness, overlap logic)
- Writing tests *first for the business rule that actually matters* (date conflicts), not just CRUD happy paths
- Setting up a CI pipeline that would actually catch a regression before merge
- Structuring a codebase for readability (routes / schemas / models / auth cleanly separated)

## Possible extensions
